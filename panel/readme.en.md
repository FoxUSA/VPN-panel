# awg-panel

A web panel to manage a VPN server from a single screen: **AmneziaWG**, **XRay (VLESS — TLS or Reality)**, **Hysteria 2** and **mtg (MTProto)**. Flask + vanilla JS, no database — state lives in JSON files.

> Russian `readme.md` is the canonical version; this file is its English translation.

## Features
- AWG / XRay / Hysteria / mtg clients: create, delete, links and QR codes, traffic limits and schedule
- Hysteria 2 is a protocol of its own: its own tab, its own `hysteria-server` service and its own clients under `data/hysteria/`. QUIC over UDP, so it never collides with XRay's TCP port. Port, masquerade site (proxy someone else's site or a bare 404), salamander obfuscation and bandwidth caps are managed from the panel; the binary updates from GitHub with a rollback if the new version fails to start
- The XRay core also carries an experimental second Hysteria entrance (a toggle under ⚙ “XRay service”). It shares the UDP port space with the standalone protocol, so it is enabled by hand only, and the panel's port registry warns about a collision
- Protocol installation from the panel: XRay, MTProto and AmneziaWG are installed with a button — the panel drops the binary (for AWG it builds the DKMS kernel module against the running kernel), generates the config, picks a free port and opens it in ufw. The AWG install runs as visible steps: kernel headers, repository, module build, server config with keys and a free subnet, interface start
- XRay in TLS and Reality modes; configs for Shadowrocket / Loon / Clash with rule sets (ready-made blackmatrix7 lists + your own), each rule carrying its own policy — through the VPN, direct, or block
- Connection logs (IP, geo, domains), traffic stats, online status
- Global routing rules, login masking behind an ordinary website, backups, automatic dependency check
- Cascade through a second VPN (mihomo): XRay, mtg and Hysteria can be routed into its socks port
- Per-client DNS: encrypted DoH/DoH3/DoQ written straight into the Shadowrocket/Loon/Clash profile, ready-made templates or your own resolver
- IP filtering: per-client allow and block lists of addresses/subnets, the rule lives in the server routing
- External monitoring by a separate utility on another server: ports, speed, uptime history, public status page (not part of this package, see `monitoring/` in the repo root)
- Updating XRay / mtg / AmneziaWG / Hysteria and the panel itself from the UI (protocol versions, auto-update via manifest)
- Admin audit log (logins, settings and client changes)
- Bilingual UI (RU/EN): language auto-detected on login, 🌐 toggle (left of ⚙), live translation with no reload; `install_interactive.html` is bilingual too

## Installation
A step-by-step interactive guide — open **`install_interactive.html`** in a browser. Only three steps are required: upload the files, install the dependencies, start the service. After that the panel opens by itself on port 8081 (`http://IP:8081`, nginx required), with an SSH tunnel as a fallback (`ssh -L 5000:127.0.0.1:5000 root@IP`), and the first-login password is generated by the panel itself and written to the service journal. Protocols and clients are configured from the web interface. Login by domain over HTTPS is step 4 of the guide: the certificate is issued on the server, and then the panel and site open at `https://domain`. The panel takes port 443 itself and gives it up when XRay or the WEB proxy appears.

Full package archive: <https://byfox.dev/data/awg-panel/awg-panel.zip>

## Updates
The panel checks its own version and updates its code from `manifest.json` at <https://byfox.dev/data/awg-panel> (button in the footer). Updates replace code only: everything user-owned lives in `data/` and is never touched.

## Geo
MaxMind GeoLite2 databases (City/ASN) are downloaded from <https://byfox.dev/data/maxmind>. The local database version is stored in `server.json` (`geo_version` field) and compared against the CDN date roughly every 180 days — if outdated, the panel offers to update.

## Languages (i18n)
Translation runs on the client: Russian is the source, the engine translates the visible DOM text into EN.
- `static/i18n.js` — engine (auto-detect, toggle, live translation of text nodes/attributes)
- `static/i18n-dict.js` — auto-generated RU→EN dictionary (exact strings + patterns + phrases)
- Geo names (country/city in logs) are translated server-side via the `lang` cookie (the only locale dependency in `app.py`)

## `deploy/` layout
- `app.py` — backend (Flask)
- `static/` — UI (`index.html` + `app.js`), localization engine (`i18n.js`, `i18n-dict.js`) and log pages (`logs.html`, `mtg_logs.html`)
- `modules/` — panel code split by domain, wired from `app.py`, routes live in Blueprints:
  - `mihomo.py` — cascade through a second VPN: config, profiles, nodes, rules, watchdog
  - `backup_update.py` — backups, schedule, restore and the `awg-panel.zip` rollout
  - `awg_install.py` — AmneziaWG install and update (DKMS) with step-by-step progress
  - `awg_dest_log.py` — AWG destination collection (conntrack + hostnames from dnsmasq)
  - `proxy_links.py` — subscription link parsing and clash-yaml assembly, stateless
  - `sys_health.py` — server health: CPU, memory, disks, network
  - `hysteria/` — the Hysteria 2 protocol as a self-contained package: service and config, clients, the auth script, stats over the Traffic Stats API, global rules and the tab's own assets (`hysteria/static/`). `app.py` wires it in with a single `register()`; without the package the panel still starts
  - `xray_hysteria.py` — the experimental Hysteria 2 inbound inside the XRay core: inbound assembly, self-signed certificate with its fingerprint, links and profile nodes
  - `hysteria_migrate.py` — a wizard that moves clients from the standalone Hysteria protocol into XRay. **Disabled in `app.py`**: it wipes everything belonging to standalone Hysteria off the server, and that protocol is back. The file is kept for later
- `manifest.json` — panel version and release date
- `public/` — fake-site pages used to mask the login, `fox.ico` — the icon
- `install_interactive.html` — interactive install guide (bilingual)
- `readme.md` / `readme.en.md` — project description (RU is canonical, EN is the translation)
- `data/` — everything user-owned: `awg/`, `xray/`, `hysteria/`, `mtproto/`, `mihomo/`, `geo_rules/`, `logs/`, `backup/` and server settings at its root (`server.json`, `admin.json`). Created by the panel on the server, not part of the repo, and survives updates

## Own rule templates — `rules/`
Live in the repo root, not in `deploy/`: sources of the own templates for the «Templates» picker (service domains + an ads/analytics/trackers blocklist). Uploaded to the CDN by hand, not part of the panel package. How it works, how to edit it and how to test it — `rules/readme.md` (RU).
