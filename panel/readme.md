# awg-panel

Веб-панель управления VPN-сервером на одном экране: **AmneziaWG**, **XRay (VLESS — TLS или Reality)**, **Hysteria 2** и **mtg (MTProto)**. Flask + ванильный JS, без БД — состояние в JSON-файлах.

## Что умеет
- Клиенты AWG / XRay / Hysteria / mtg: добавление, удаление, ссылки и QR, лимиты и расписание трафика
- Hysteria 2 — самостоятельный протокол со своей вкладкой, своим сервисом `hysteria-server` и своими клиентами в `data/hysteria/`. QUIC поверх UDP: с TCP-портом XRay не пересекается. Порт, маскировочный сайт (проксирование чужого сайта либо голый 404), обфускация salamander и потолки полосы — из панели; обновление бинаря с GitHub кнопкой, с откатом, если новая версия не стартовала
- Внутри ядра XRay есть второй, экспериментальный вход Hysteria (тумблер в ⚙ «Сервис XRay»). Он делит пространство UDP-портов с самостоятельным протоколом, поэтому включается только руками, а реестр портов панели предупреждает о столкновении
- Установка протоколов из панели: XRay, MTProto и AmneziaWG ставятся кнопкой — панель кладёт бинарь (для AWG собирает DKMS-модуль ядра под текущее ядро), генерирует конфиг, подбирает свободный порт и открывает его в ufw. Установка AWG идёт по шагам с показом прогресса: заголовки ядра, репозиторий, сборка модуля, серверный конфиг с ключами и свободной подсетью, запуск интерфейса
- XRay в режиме TLS и Reality; конфиги для Shadowrocket / Loon / Clash с наборами правил (готовые списки blackmatrix7 + свои), у каждого правила своя политика — через VPN, напрямую или блок
- Логи подключений (IP, гео, домены), статистика трафика, онлайн-статус
- Глобальные правила маршрутизации, маскировка входа под обычный сайт, бэкапы, авто-проверка зависимостей
- Каскад через второй VPN (mihomo): XRay, mtg и Hysteria можно завести в его socks-порт
- DNS для клиентов: шифрованный DoH/DoH3/DoQ прямо в профиле Shadowrocket/Loon/Clash, готовые шаблоны или свой резолвер
- Фильтрация по IP: белый и чёрный список адресов/подсетей у клиента, правило живёт в серверном роутинге
- Внешний мониторинг отдельной утилитой на другом сервере: порты, скорость, история аптайма, публичная страница статуса (не часть этого пакета, см. `monitoring/` в корне репозитория)
- Обновление XRay / mtg / AmneziaWG / Hysteria и самой панели из интерфейса (версии протоколов, авто-апдейт по манифесту). Модуль AWG пересобирается под текущее ядро; остановленный интерфейс панель не поднимает
- Журнал действий администратора (входы, изменения настроек и клиентов)
- Двуязычный интерфейс RU/EN: авто-определение языка при входе, переключатель 🌐 (слева от ⚙), перевод на лету без перезагрузки; `install_interactive.html` тоже двуязычный

## Установка
Пошаговый интерактивный гайд — открой **`install_interactive.html`** в браузере. Обязательных шагов три: залить файлы, поставить зависимости, запустить сервис. Дальше панель сама открывается на порту 8081 (`http://IP:8081`, нужен nginx), пароль первого входа она генерирует сама и пишет в журнал сервиса. Запасной вход — SSH-туннель (`ssh -L 5000:127.0.0.1:5000 root@IP`). Протоколы и клиенты настраиваются уже из веб-интерфейса. Вход по домену и HTTPS — шаг 4 гайда: сертификат выпускается на сервере, после этого панель и сайт открываются на `https://домен`. Порт 443 панель занимает сама и уступает его, когда появляется XRay или WEB-прокси.

Готовый архив всего пакета: <https://byfox.dev/data/awg-panel/awg-panel.zip>

## Обновление
Панель сама проверяет версию и обновляет код по `manifest.json` с <https://byfox.dev/data/awg-panel> (кнопка в подвале). Обновление заменяет только код: всё пользовательское живёт в `data/` и не трогается.

## Гео
Базы MaxMind GeoLite2 (City/ASN) панель качает с <https://api.byfox.dev/geo/>. Локальная версия баз хранится в `server.json` (поле `geo_version`) и раз в ~180 дней сверяется с датой на сервере — если устарела, панель предложит обновить.

## Шаблоны правил
Каталог шаблонов (зеркало blackmatrix7 и свои шаблоны byFox, с подсказками) и индекс поиска «Домен или IP» панель берёт с <https://api.byfox.dev/rule/>: раз в сутки сверяет `rule/manifest.json` и качает только изменившееся. Клиентские профили тоже ссылаются на файлы правил там, а не на GitHub. Исходники своих шаблонов живут в проекте api.byfox.dev, не в панели.

## Языки (i18n)
Перевод выполняется на клиенте: русский — источник, движок переводит видимый DOM-текст в EN.
- `static/i18n.js` — движок (авто-детект, переключатель, перевод текст-нод/атрибутов на лету)
- `static/i18n-dict.js` — авто-генерируемый словарь RU→EN (точные строки + паттерны + фразы)
- Гео-имена (страна/город в логах) переводит сервер по cookie `lang` (единственная локаль-зависимость в `app.py`)

## Состав `deploy/`
- `app.py` — бэкенд (Flask): единственный `.py` в корне, создаёт приложение и подключает модули
- `static/` — UI (`index.html` + `app.js`), движок локализации (`i18n.js`, `i18n-dict.js`) и страницы логов (`logs.html`, `mtg_logs.html`)
- `modules/` — код панели по доменам; подключается из `app.py`, роуты живут в Blueprint'ах:
  - `mihomo.py` — каскад через второй VPN: конфиг, профили, узлы, правила, watchdog
  - `backup_update.py` — бэкапы, расписание, restore и накат `awg-panel.zip`
  - `awg_install.py` — установка и обновление AmneziaWG (DKMS) с пошаговым прогрессом
  - `awg_dest_log.py` — сбор destinations AWG (conntrack + домены из dnsmasq)
  - `proxy_links.py` — разбор ссылок подписок и сборка clash-yaml, без состояния
  - `sys_health.py` — здоровье сервера: CPU, память, диски, сеть
  - `hysteria/` — протокол Hysteria 2 отдельным пакетом: сервис и конфиг, клиенты, скрипт авторизации, статистика через Traffic Stats API, глобальные правила и своя статика вкладки (`hysteria/static/`). Подключается из `app.py` одним `register()`; если пакета нет, панель поднимается без него
  - `xray_hysteria.py` — экспериментальный инбаунд Hysteria 2 внутри ядра XRay: сборка инбаунда, самоподписанный сертификат с отпечатком, ссылки и узлы для профилей
  - `hysteria_migrate.py` — мастер переноса клиентов со отдельного протокола Hysteria в XRay. **Отключён в `app.py`**: он вычищает с сервера всё, что относится к самостоятельной Hysteria, а протокол вернулся. Файл оставлен на будущее
- `manifest.json` — версия панели и дата релиза
- `public/` — страницы фейк-сайта для маскировки входа, `fox.ico` — иконка
- `install_interactive.html` — интерактивная инструкция установки (двуязычная)
- `readme.md` / `readme.en.md` — описание проекта (RU — каноничен, EN — перевод)
- `data/` — всё пользовательское: `awg/`, `xray/`, `hysteria/`, `mtproto/`, `mihomo/`, `geo_rules/`, `logs/`, `backup/` и настройки сервера в корне (`server.json`, `admin.json`). Создаётся панелью на сервере, в репозиторий не входит и переживает обновления

## Свои шаблоны правил — `rules/`
Лежат в корне репозитория, не в `deploy/`: исходники своих шаблонов для пикера «Шаблоны» (домены сервисов + блок рекламы/аналитики/трекеров). Заливаются на CDN вручную, в пакет панели не входят. Как устроено, как править и как проверять — `rules/readme.md`.
