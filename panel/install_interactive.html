Зависимости
выполнить
apt-get update && apt-get install -y python3-venv nginx cd /opt/awg-panel python3 -m venv venv ./venv/bin/pip install gunicorn flask maxminddb
Пакет maxminddb нужен для гео в логах. Забыли — панель всё равно запустится и предложит доустановить его в «Зависимостях».

2
Запуск и первый вход
создать сервис
cat > /etc/systemd/system/awg-panel.service << 'EOF' [Unit] Description=AWG Panel After=network.target [Service] Type=simple WorkingDirectory=/opt/awg-panel ExecStart=/opt/awg-panel/venv/bin/gunicorn --bind 127.0.0.1:5000 --workers 1 --threads 4 --timeout 120 app:app Restart=always RestartSec=5 User=root [Install] WantedBy=multi-user.target EOF
запустить
systemctl daemon-reload systemctl enable awg-panel systemctl start awg-panel
статус
systemctl status awg-panel --no-pager -l
Пароль панель создала сама при первом запуске и записала в журнал сервиса — забираем его:
показать пароль и адрес
journalctl -u awg-panel --no-pager | grep -A2 "Пароль первого входа" | tail -3 cat /opt/awg-panel/data/first_login.txt
Пароль временный: панель попросит сменить его при первом входе, после смены файл first_login.txt удаляется сам.
Панель сама открыла порт 8081. Откройте адрес из файла, например http://IP_СЕРВЕРА:8081, и войдите этим паролем. Дальше всё делается в панели: протоколы, клиенты, настройки.
Пока нет сертификата, вход идёт по http без шифрования, и пароль передаётся открытым. Для постоянной работы выпустите сертификат на шаге 4.
Адрес не открывается? Откройте порт 8081 в фаерволе хостера. Адреса нет в файле — значит, nginx не поставился. В любом случае можно зайти через SSH-туннель:
на своём компьютере
ssh -L 8080:127.0.0.1:5000 root@IP_СЕРВЕРА
Не закрывая это окно, откройте http://localhost:8080.
опционально: вставьте выводожидание вывода
Ожидаем active (running).

4
Домен и HTTPS (необязательно)
Панель уже открыта по IP. Этот шаг нужен, чтобы входить по домену и по HTTPS. После него панель и сайт откроются на https://домен:8081.
Порт 443 панель занимает сама, пока он свободен, и уступает его, когда появляется XRay или WEB-прокси. Адрес https://доменпри этом продолжит работать за XRay в режиме TLS. Порядок важен: сначала сертификат, потом XRay. Кнопка установки сама выбирает режим: сертификат есть — TLS, сертификата нет — Reality.
Домен с A-записью на IP этого сервера. Он же подставится в server.json на шаге 3.
Режим XRay:
Свой домен + TLSВход по домену, нужен сертификат
RealityМаскировка под чужой сайт, сертификат не нужен
TLS — нужен домен с A-записью на IP. Лучшая обфускация (DNS, IP, серт — всё совпадает). Панель открывается через браузер.
Reality — сертификат не нужен. Xray притворяется чужим сайтом. Панель останется на порту 8081 — см. вкладку «Доступ к панели».
Выпускаем сертификат Let's Encrypt. Порт 80 должен быть открыт, в том числе в фаерволе хостера.
1. поставить certbot
apt-get install -y certbot mkdir -p /var/www/acme rm -f /etc/nginx/sites-enabled/default
2. конфиг для проверки домена
cat > /etc/nginx/sites-available/DOMAIN << 'EOF' server { listen 80; listen [::]:80; server_name DOMAIN; location ^~ /.well-known/acme-challenge/ { root /var/www/acme; } location / { return 301 https://$host$request_uri; } } EOF
3. включить
ln -sf /etc/nginx/sites-available/DOMAIN /etc/nginx/sites-enabled/ nginx -t && systemctl reload nginx
опционально: вставьте выводожидание вывода
4. получить сертификат
certbot certonly --webroot -w /var/www/acme -d DOMAIN --non-interactive --agree-tos --register-unsafely-without-email
Должны увидеть строку Successfully received certificate. и пути к файлам fullchain.pem и privkey.pem.
опционально: вставьте вывод certbotожидание вывода
Плагин certbot --nginx здесь не используйте: он добавит в nginx listen 443 ssl, а этот порт нужен XRay.
5. включить HTTPS на панели
systemctl restart awg-panel
Через минуту панель откроется на https://домен и https://домен:8081. Старый адрес по http перестанет работать.
Нужен VPN? Установите XRay: вкладка XRay в панели → кнопка установки. Сертификат панель найдёт сама и поставит XRay в режиме TLS.
XRay уже стоит в Reality? Переключите его: вкладка XRay → ⚙ → «Режим на 443» → TLS.
На сервере ничего делать не нужно: панель уже открыта на порту 8081. XRay ставится кнопкой на вкладке XRay.

Как зайти в панель в разных режимах XRay. Панель сама детектит TLS/Reality и в разделе ⚙ → Страница входа показывает рабочий адрес. Ниже — что выбрать в каждом случае. Везде <IP>, <домен>, <ключ>, <порт> — подставь свои.
★
Универсально: SSH-туннель (работает всегда)
Если снаружи панель закрыта (Reality, сбитая маскировка, потерян адрес) — заходишь напрямую к gunicorn через туннель. Через него же можно настроить всё остальное.
на своём компьютере
ssh -L 8080:127.0.0.1:5000 root@<IP>
Оставь окно открытым → открой в браузере http://localhost:8080 (если маскировка/ключ — http://localhost:8080/<ключ>).
1
XRay в режиме TLS (сертификат на домен)
Панель едет на 443 «прицепом»: XRay-TLS → fallback → nginx → панель. Отдельный порт не нужен.
Вход: https://<домен>/ — или https://<домен>/<ключ>, если включена маскировка.
В Страница входа выбери «Вход по IP» (корень = панель) или «Маскировка фейк-сайтом» (корень = сайт, панель по ключу).
2
XRay в режиме Reality
443 целиком занят Reality (уводит на dest-сайт) — на 443 панель НЕ отдаётся. Нужен отдельный порт.
1. Первый вход — по адресу из first_login.txt (порт 8081) или через SSH-туннель (см. выше).
2. ⚙ → Страница входа → Доступ к панели по порту → впиши порт (напр. 2096) → выбери режим «Только по ключу» → Сохранить. Панель сама поднимет nginx и откроет порт в ufw.
Вход: https://<домен>:<порт>/<ключ> (TLS, если есть серт) или http://<IP>:<порт>/<ключ> (если серта нет).
Конфиг XRay/Reality панель не трогает — поднимает только свой отдельный nginx-блок awg-panel-access.
→
Переезд: был TLS, стал Reality
Был доступ https://<домен>/. После смены XRay на Reality 443 перестаёт отдавать панель — веб-доступ пропадёт.
1. Зайди через SSH-туннель.
2. Страница входа → задай порт → режим «Только по ключу» → Сохранить.
Новый вход: https://<домен>:<порт>/<ключ>.
←
Переезд: был Reality, стал TLS
Вернул XRay на TLS+fallback на 443 → панель снова доступна на 443 через домен. Отдельный порт больше не нужен.
1. Зайди по старому порту (если оставлял) или через SSH-туннель.
2. Страница входа → очисти поле порта → Сохранить (порт закроется в ufw, nginx-блок снимется). Режим верни на «Маскировка» или «Вход по IP».
Вход: https://<домен>/<ключ> (или https://<домен>/ без маскировки).
!
Потерял адрес входа
Сбрось маскировку и key-only через SSH — панель вернётся на корень (доступный через 443-TLS / порт / туннель):
на сервере
sed -i 's/"fake_enabled": true/"fake_enabled": false/;s/"login_block_root": true/"login_block_root": false/' /opt/awg-panel/data/server.json && systemctl restart awg-panel
Это не закрывает отдельный порт (он в ufw/nginx). Снять порт — в Страница входа, очистив поле порта.
